# Anti-AI-Slop Design

Make the result feel like a mature software engineering, automation, and integrations company. Apply this skill with `truetell-design-system` whenever UI is created or reviewed.

## Reject by default

- The stock hero formula: kicker + giant H1 + paragraph + two CTAs + decorative object; repeated eyebrow/kicker labels; decorative `AI • SOFTWARE • AUTOMATION`-style lines.
- Gradient text, blue-purple gradients, cyan or neon glow, floating blobs, particles, 3D spheres/cubes, glowing pseudo-technology, generic AI robots/brains/holograms, and purposeless dashboard mockups.
- Excessive glass, a glass/card container around every block, icon-in-circle patterns, colored circular icon backdrops, identical rounded cards, large radii, pill buttons without a functional reason, large soft SaaS shadows, and decorative lines or dots.
- Empty marquees, decorative monospace, oversized marketing headlines, and stock claims such as “раскройте потенциал”, “новое поколение”, “будущее бизнеса”, or “революционные решения”.

## Prefer

Use typography, grid, whitespace, meaningful data, real interfaces, architectural diagrams, tables, statuses, connection maps, system states, and restrained motion that explains system behavior.

## AI-slop review

Before completing UI work, inspect the result and fix problems yourself:

1. Could it be mistaken for a generic AI/SaaS template?
2. Does every visual element serve comprehension, hierarchy, data, or an action?
3. Are there too many cards, rounded corners, icons, or competing primary treatments?
4. Would text, data, or a real interface explain the idea better than an icon or decoration?
5. Does it read as a mature engineering company at desktop and mobile sizes?

Do not merely report slop: remove or replace it, then recheck.
