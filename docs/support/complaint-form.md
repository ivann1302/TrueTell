# Жалобы на приложения TrueTell

Правило владельца от 13.10.2026. Страница: https://truetell-retail.ru/complaints/.

Приложение открывает форму в новой вкладке обычной ссылкой по действию пользователя, с `target="_blank" rel="noopener noreferrer"`. Это отдельная страница сайта, без встраивания в iframe Битрикс24. Ссылка передаёт только постоянный код `app`, без OAuth, CRM-данных, идентификаторов пользователя и копирования query-параметров текущего iframe.

## Приложения и ссылки

Единый реестр названий и кодов: `src/config/support-applications.json`. Сборка копирует его в `backend/config/support-applications.json`; сервер проверяет тот же список. Для нового приложения сначала добавляется запись в реестр, затем в приложение — ссылка со стабильным кодом. Название не передаётся произвольной строкой и не определяется через Referer.

| Приложение | Ссылка из приложения |
|---|---|
| Массовое удаление лидов и сделок | https://truetell-retail.ru/complaints/?app=cleaner |
| Очистка полей | https://truetell-retail.ru/complaints/?app=field-cleaner |
| Рейтинг продаж | https://truetell-retail.ru/complaints/?app=product-rating |
| График платежей | https://truetell-retail.ru/complaints/?app=payment-schedule |
| Справочник полей CRM | https://truetell-retail.ru/complaints/?app=crm-fields |

При известном `app` выбранное название подставляется автоматически. При неизвестном или отсутствующем коде поле остаётся пустым. Пользователь может выбрать другое приложение из списка. Отправка без выбранного приложения запрещена и в браузере, и на сервере.

## Форма и обработка

Обязательны приложение, описание проблемы, имя, способ связи/контакт и отдельное согласие. По умолчанию Telegram; также доступны телефон, MAX и WhatsApp. Проверяется формат, без кода подтверждения владения. Telegram нормализуется в `@username`; телефонные контакты используют формат `+7 (999) 999-99-99`. Чужой код страны и лишние цифры отклоняются до маскирования.

`POST /api/complaints` использует существующие web/CSRF middleware, общий лимит заявок (5 в минуту, 100 в сутки на IP), honeypot и уникальный ключ отправки. Приложение проверяется по реестру; источник и путь формируются сервером. Жалоба сохраняется в существующую CRM, описание/имя/контакт шифруются. В карточке источник содержит приложение, текст начинается с его названия. Новые таблицы и миграции не нужны.

Повтор неизменной отправки сохраняет ключ и не создаёт дубль. Изменение данных после неопределённого ответа создаёт новый ключ. Сервер возвращает 409, если прежний ключ используется с другим содержимым. До подтверждения сервера значения остаются в форме.

Существующий Telegram-бот, получатели, cron, очередь и формат уведомления сохраняются. Уведомление содержит номер и защищённую ссылку в CRM, без имени, контакта и текста. Отказ Telegram не отменяет запись жалобы; повтор доставки выполняется существующим механизмом.

Страница имеет `noindex, follow`, собственный canonical и исключается из sitemap/IndexNow. robots.txt оставляет её доступной для чтения noindex. В публичное меню и каталог продуктов ссылка не добавляется.

## Приёмка

Проверить известный/неизвестный код, все обязательные поля и контакты, CSRF, honeypot, лимит запросов, одинаковые/изменённые повторы, сохранность текста при ошибке. Проверить 320/390/768/1440 px, клавиатуру, отсутствие горизонтального переполнения, опубликованный noindex и отсутствие в sitemap. Живую CRM/Telegram проверять одной явно помеченной синтетической жалобой; результаты и очистку записывать в протокол выпуска.
