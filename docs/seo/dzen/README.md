# Выпуск статьи блога в Дзене

Правило владельца от 30.10.2026: при выпуске новой опубликованной статьи блога
готовить отдельную авторскую версию для Дзена и пригодные изображения в том же
редакционном цикле. Это обязательный шаг сборки и CI/CD. Статьи базы знаний
пока не входят в этот поток.

## Порядок

1. Выберите тему, целевое приложение и конкретную проверенную возможность.
   Продуктовый переход на исходной статье должен вести к действующей карточке,
   продуктовой странице или консультации в соответствии со статусом продукта.
2. Подготовьте статью на сайте по `docs/seo/content-publishing.md`, включая
   фактологическое ревью, humanizer, два смысловых изображения и отметку в
   `docs/seo/humanizer-reviews.json`.
3. В `adaptations.json` добавьте запись по `hrefPath` статьи: отдельные
   заголовок, описание, три абзаца вступления и первый абзац основного текста.
   В `sections.json` добавьте новые начала ровно двух тематических разделов
   по точным текстам их H2. Сохраняйте факты, числа, ограничения и ссылки.
4. Выберите `delivery`: по умолчанию `rss`; для ручной публикации укажите
   `"manual"` до подачи ленты. Проверяйте, чтобы один материал не отправлялся
   обоими способами. После ручной публикации внесите её URL в редакционный
   отчёт.
5. Выполните `npm run build`. Скрипт `scripts/dzen-feed.mjs` читает реестр
   `src/config/articles.ts` и собранный HTML, добавляет адаптацию и существующий
   продуктовый CTA страницы. Он создаёт `dist/dzen.xml` для RSS-статей и
   локальные полные копии всех подготовленных статей в
   `.generated/dzen-editor-html/<slug>/article.html`. Рядом с каждой копией
   лежат файлы её изображений для ручной загрузки. CI сохраняет эту папку
   как артефакт `dzen-editor-package` на семь дней.
6. Проверьте копию: заголовок, переход к приложению, факты, ссылки, подписи,
   мобильное чтение и порядок изображений. Запустите тесты и остальные
   проверки из `docs/seo/content-publishing.md`. Публикация сайта и подача
   RSS в Студии Дзена остаются отдельными действиями с разрешения владельца.

## Что останавливает CI

В `npm run build` и GitHub Actions сборка завершается ошибкой, если для
новой опубликованной статьи блога нет адаптации, один из двух разделов не
найден в собранном тексте, отсутствует исходный HTML, в статье меньше двух
изображений либо любой файл изображения отсутствует в `dist`, имеет формат
вне JPEG/PNG/GIF или ширину меньше 700 px. Изображения со страницы,
оптимизированные для сайта в WebP, для Дзена берутся из оригинальной ссылки
JPEG/PNG. Если исходник слишком узкий, подготовьте отдельный подходящий файл
в `public/dzen-images/` и проверьте подпись и реальный размер.

Тест `scripts/dzen-feed.test.mjs` сверяет состав RSS с редакционными данными,
проверяет обложки и продуктовый переход, а также локальный комплект ручной
пробной статьи. CI запускает тест после сборки. Сборка создаёт файлы, но не
пишет авторский текст и не отправляет материал в Дзен сама. После подключения
RSS Дзен считывает опубликованную ленту со своего адреса; решение о приёме
остаётся за Дзеном.

## Состояние перехода на 30.10.2026

Для 12 статей блога адаптации готовы. Статья
`audit-poley-crm-bitrix24/` включена в первую RSS-подборку по решению владельца
от 30.10.2026; отдельно вручную её не публикуем. Четыре старые опубликованные
статьи перечислены в `legacy-exclusions.json`: они вышли до нового правила
и пока не имеют авторской адаптации. Эти исключения не распространяются на
новые публикации. До отправки RSS их следует отдельно подготовить или
осознанно оставить вне ленты.

Публичный `https://truetell-retail.ru/dzen.xml` станет доступен только
после деплоя. Не вставляйте этот адрес в Студию Дзена, пока он
не открывается по HTTP и не проверены изображения.
