# Вебхуки МойСклад. Обновление №168 от 19.11.2026

SEO-122, UPDATE, База знаний, `/vebhuki-moysklad/`. Статья помогает выбрать уведомление для события и проверить доставку и итоговую запись. Соседние статьи объясняют первый запрос к API и смысл показателей остатков. Из обновлённого текста есть переходы к обеим и к сценарию MCP. Входящий переход есть из каталога базы знаний.

## Факты и изображения

- В Сценариях пример использует подстановки ID и типа документа. Для заказа покупателя приведён `CustomerOrder`. Добавлен оригинальный экран действия «Отправить вебхук» с пустым полем адреса. [Справка о Сценариях](https://support.moysklad.ru/hc/ru/знакомство%20с%20сервисом/инструменты/вебхуки), [оригинал снимка](https://support.moysklad.ru/hc/_next/static/media/360018141917.00d5cc8a.png).
- Вебхук объекта JSON API содержит массив `events` и метаданные объекта. Для вебхуков объектов и остатков действуют коды 200/204, срок 1 500 мс и три последовательные дополнительные попытки. У одного уведомления сохраняется `requestId`. Эти условия приведены по документации 1.2. [Вебхуки объектов](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/dictionaries/_webhook.md), [вебхуки остатков](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/dictionaries/_webhookstock.md).
- `webhookstock` передаёт ссылку `reportUrl` на краткий отчёт. Подписка описана для `stock`. В примере `bystore` сопоставляются товар и склад. `changedSince` ограничивает состав товаров с изменениями, значения в отчёте текущие. [Отчёт об остатках](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/reports/_report_stock.md).
- Учебная инфографика показывает HTTP 204 на приёмнике, 9 штук в отчёте и 12 на витрине. Проверка повтора выполняется с тем же `requestId` на тестовом приёмнике. Доставка уведомления, чтение отчёта и запись сверяются отдельно. Реальный вебхук и клиентский аккаунт для этой статьи не использовались.

## Редакционная проверка

Humanizer применён к заголовкам, вступлению, основному тексту, таблице, FAQ, подписям и метаданным. Общие схемы заменены демонстрационным экраном Сценариев и учебной сверкой остатка. Уточнено, что повтор запроса после принятия в очередь — отдельная задача интеграции. Отпечаток записан в `humanizer-reviews.json`.

Независимое ревью сверило первоисточники, три механизма уведомлений, поля, таймаут, повтор и обработку остатков. Проверены источник снимка, согласованность примера и самостоятельность интента. По итоговым замечаниям уточнены одинаковый показатель на витрине и в отчёте, назначение `bystore` и проверка адреса перед запросом с авторизацией.
