# Исправление автоматического деплоя TrueTell на SprintHost

## Цель

Восстановить автоматическую публикацию статической сборки TrueTell на SprintHost после каждого успешного push в ветку `main`.

## Исходное состояние

- CI в `.github/workflows/deploy.yml` успешно устанавливает зависимости, запускает ESLint, тест IndexNow, production-сборку Astro и проверку результата.
- FTP-секреты `FTP_HOST`, `FTP_USER`, `FTP_PASSWORD` и `FTP_REMOTE_PATH` настроены и проходят проверку workflow.
- Деплой останавливается с ошибкой `FTPError: 500 This security scheme is not implemented`.
- TrueTell принудительно использует explicit FTPS через `protocol: ftps`.
- Рабочий локальный проект `sk-rosa` использует тот же `SamKirkland/FTP-Deploy-Action@v4.3.5` и те же четыре FTP-секрета, но не задаёт `protocol`; действие использует обычный FTP по умолчанию.

## Решение

В workflow TrueTell явно установить `protocol: ftp`. Явное значение сохраняет поведение рабочей схемы `sk-rosa` и делает выбранный транспорт заметным при дальнейшем сопровождении.

Другие части цепочки не менять:

- проверки запускаются для push и pull request;
- публикация запускается только после успешной сборки для push в `main`;
- загружается каталог `dist/` в `FTP_REMOTE_PATH`;
- `dangerous-clean-slate` остаётся выключенным;
- после успешной публикации запускается IndexNow;
- основной и канонический домен остаётся `https://truetell-retail.ru`.

Документацию деплоя нужно привести в соответствие с фактическим протоколом и прямо указать, что обычный FTP не шифрует учётные данные и файлы при передаче.

## Поток выполнения

1. GitHub получает push.
2. Job `build` устанавливает зависимости, проверяет код, собирает сайт и загружает `dist/` как artifact.
3. Для ветки `main` job `deploy` проверяет наличие Secrets и синхронизирует artifact с каталогом сайта на SprintHost по FTP.
4. После успешной загрузки job `indexnow` проверяет опубликованные файлы и уведомляет участников IndexNow.

## Обработка ошибок

- Отсутствующие FTP-секреты или небезопасно широкий `FTP_REMOTE_PATH` останавливают деплой до соединения с сервером.
- Ошибка FTP оставляет job `deploy` красной и не запускает IndexNow.
- Ошибка IndexNow не откатывает уже опубликованный сайт; упавшую job можно запустить повторно.
- Публикация остаётся инкрементальной и неатомарной; `dangerous-clean-slate: false` не позволяет workflow очищать весь удалённый каталог.

## Проверка

Локально выполнить обязательные проверки проекта:

```sh
node --test scripts/*.test.mjs
npm run lint
npm run build
node scripts/indexnow.mjs --check
```

После push в `main` убедиться, что jobs `build`, `deploy` и `indexnow` завершились успешно, а `https://truetell-retail.ru/` отдаёт опубликованную сборку по HTTPS.

## Ограничение безопасности

Обычный FTP не шифрует соединение. Это осознанное повторение работающей конфигурации `sk-rosa`, выбранное потому, что FTP-сервер SprintHost отвергает explicit FTPS. Если для аккаунта SprintHost будет подтверждён доступ по SSH/SFTP из GitHub Actions, отдельной задачей можно заменить транспорт без изменения процесса сборки.
