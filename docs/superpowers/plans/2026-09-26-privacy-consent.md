# TrueTell: план оформления обработки данных и управления аналитикой

> Для исполнителя: выполнять по `executing-plans`, последовательно, с проверкой каждого этапа. Это проект решения для обсуждения, а не подтверждение юридического соответствия и не выполненная реализация.

> **Обновление после согласования:** пользователь попросил короткий текст про cookie и маленькое мобильное окно. Актуальная реализация и скриншоты — [privacy-implemented/README.md](privacy-implemented/README.md). Ранние макеты ниже сохранены как история; их большие размеры больше не являются спецификацией.

**Цель:** опубликовать достоверные документы и дать посетителю понятный выбор, который действительно управляет Метрикой.

**Архитектура:** статические страницы Astro, общий компонент согласия в BaseLayout, небольшой клиентский TypeScript-модуль без React и внешней CMP. Стили SCSS Modules. Серверная часть не добавляется.

**Стек:** существующие Astro, TypeScript, SCSS, браузерный `<dialog>`, localStorage, node:test. Новые production-зависимости не нужны.

**Спецификация:** разделы 1–8 этого документа; визуальная спецификация — [галерея](privacy-preview/index.html). Все изображения — макеты, наложенные на локальный текущий сайт; они не показывают уже реализованную функциональность.

## 1. Границы и исходное состояние

Основание: отчёт `152fz-otchet-truetell-retail.ru-2026-09-25.pdf` от 25.09.2026 и проверка исходников 26.09.2026.

- В `src/layouts/BaseLayout.astro` Метрика 103366745 запускается после load/idle без проверки согласия; включены webvisor, clickmap, trackLinks.
- Отдельный noscript-пиксель также отправляет запрос на mc.yandex.ru.
- В `src/components/footer/site-footer.astro` отсутствуют политика и управление приватностью.
- `src/config/company.ts` содержит сокращённое имя ИП, ИНН, ОГРНИП и email, но не полный набор данных для документа.
- Форм сбора контактов на текущих страницах не обнаружено. Не добавляем форму или лишние чекбоксы только ради отчёта.
- Старые React-компоненты и разрешения CSP не доказывают, что соответствующие внешние сервисы реально загружаются. Инвентаризацию проводить на собранных действующих маршрутах и в сети браузера.
- Внешние CRM-приложения и переписка не становятся соответствующими требованиям автоматически после изменения сайта.

Глобальные ограничения: static-first; без backend/SSR; SCSS; все сведения о компании из company.ts; существующая дизайн-система; отсутствие необязательных запросов до согласия; одинаковый доступ к контенту при принятии и отказе.

## 2. Варианты решения

| Вариант | Плюсы | Ограничения |
| --- | --- | --- |
| **Метрика после согласия, Вебвизор отключён — основной проект** | Сохраняет согласованную аналитику, уменьшает объём наблюдения | Посещаемость неполная; нужен механизм управления выбором |
| Метрика и Вебвизор после согласия | Доступны записи посещений | Требуется проверить маскирование данных, настройки и отдельно ясно описать записи |
| Отключить аналитику | Самый простой интерфейс; аналитическое согласие не нужно | Нет Метрики; политика для иных фактических процессов может всё равно требоваться |

Первый вариант принят как рабочее допущение для макетов, не как подтверждённый выбор владельца. При выборе Вебвизора изменить текст, перечень данных, конфигурацию и проверки. Не добавлять фиктивный выключатель Вебвизора в интерфейс, если его нельзя независимо и корректно реализовать.

## 3. Входные данные и блокирующие публикацию решения

До выпуска документов владелец подтверждает:

1. Полное ФИО оператора и достоверность реквизитов; не выводить ФИО из инициалов догадкой.
2. Адрес для обращений, допустимый для публикации, и действующий email. Не публиковать предполагаемый домашний адрес.
3. Кто принимает запросы и отзывы согласия, как они обрабатываются.
4. Хостинг, регион хранения, состав и сроки технических журналов; данные берутся у провайдера, не из предположения о статическом сайте.
5. Владелец счётчика Метрики, настройки, получатели, сроки и договорные условия.
6. Реальный маршрут обращений из Telegram/email в CRM, сроки хранения и доступы.
7. Состояние уведомления РКН, вопросы локализации/передачи и применимые основания — отдельная организационная проверка.
8. Как обеспечивается доказуемость согласия. Локальная запись браузера помогает управлять загрузкой, но сама по себе не даёт оператору надёжный централизованный журнал доказательств. Если нужен серверный журнал, это отдельное согласуемое расширение архитектуры; не отправлять IP/идентификаторы на случайный внешний сервис.

Пока сведения не подтверждены, допустимы макеты и подготовка кода; нельзя публиковать документ с выдуманными данными или обещанием «данные не передаются третьим лицам».

## 4. Экраны и тексты

### 4.1. Первый визит — немодальный баннер

Desktop: нижний левый угол, ширина 560 px, отступы от краёв 24 px, внутренний отступ 24 px, радиус 14 px. Не затемняет страницу, не перехватывает фокус, не блокирует чтение.

Mobile: нижняя панель с отступами 12 px, ширина экрана минус 24 px, кнопки вертикально, область действия не меньше 48 px. Учитывать safe-area. При малой высоте ограничить панель по высоте и разрешить внутреннюю прокрутку. Панель не должна создавать недоступный участок контента: после реализации зарезервировать её высоту в конце документа и проверить видимость фокусируемых элементов за панелью.

Текст:

> **Аналитика сайта**
> С вашего согласия Яндекс Метрика поможет нам понять, как используют сайт. Без согласия аналитика отключена. Подробнее об обработке данных.

Действия: **Без аналитики**, **Разрешить аналитику**, **Настроить**. Отказ доступен одним нажатием, читаем и не скрыт ссылкой мелким шрифтом. Ссылка рядом ведёт к документу; до публикации проверить, что текст и действие однозначно соответствуют отдельному согласию.

Крестика нет: пользователь может читать сайт без выбора; закрытие через «Без аналитики» имеет явный смысл. Прокрутка, продолжение использования сайта и переход по ссылке не считаются согласием.

### 4.2. Настройки — desktop modal / mobile bottom sheet

Desktop: модальное окно 640 px, паддинг 32 px, радиус 20 px, затемнение фона. Mobile: снизу, паддинг 24 px, верхние углы 20 px, максимальная высота `100dvh - 24px`, внутренняя прокрутка. Одна модалка, без второго окна подтверждения поверх неё.

Заголовок: **Настройки приватности**.

Вводный текст: «Вы решаете, разрешать ли аналитику. Изменить выбор можно в подвале любой страницы».

Две строки с разделителями:

- **Сохранение вашего выбора** — «Запоминаем настройки в этом браузере, чтобы не спрашивать при каждом переходе». Состояние «Всегда активно». Это не согласие на технические cookies вообще, а описание конкретного хранения настройки.
- **Яндекс Метрика** — «Помогает оценивать посещаемость и переходы по сайту. Вебвизор отключён». Настоящий checkbox либо switch с доступным именем, выключен при первом визите.

Ссылки: «Политика обработки данных», «Согласие на аналитику».

Перед кнопками: «Включая аналитику и нажимая „Сохранить выбор“, вы даёте согласие на её использование».

Кнопки: **Без аналитики**, **Сохранить выбор**. Переключатель изменяет только черновик; применение происходит при сохранении. Отказ применяется сразу. Закрытие крестиком/Escape/по фону не сохраняет черновик. Для нового посетителя возвращается баннер; при ранее сохранённом выборе остаётся прежнее состояние.

Нативный dialog: focus внутри окна, Tab/Shift+Tab, Escape, возврат фокуса на вызвавшую кнопку. Заблокировать фоновую прокрутку; сохранить позицию. Диалог открывается только действием пользователя. На мобильном тестировать короткий landscape viewport, крупный шрифт и экранную лупу.

### 4.3. Сохранение и отзыв

После сохранения окно закрывается. Короткое сообщение через `role=status`: «Аналитика разрешена» или «Аналитика отключена». Отдельная модалка «Успешно» не нужна.

Если уже запущенная аналитика выключается: сохранить отказ, отменить отложенный запуск, прекратить работу счётчика поддерживаемым API после проверки актуальной документации, удалить доступные first-party cookies счётчика и перезагрузить страницу с отказом. Очистка чужих/HttpOnly cookies из JavaScript невозможна; не обещать полное удаление данных в Яндексе. Отзыв не отменяет запросы, уже сделанные до него. Возобновление аналитики — только новым положительным действием.

### 4.4. Подвал

Сохранить текущую композицию и реквизиты. Добавить компактный блок:

- Политика обработки данных → `/privacy/`.
- Согласие на аналитику → `/analytics-consent/`.
- Настройки приватности → button, открывающий dialog.
- Видимый email для обращений и подтверждённый почтовый адрес из company.ts.

Без JavaScript вместо неработающей кнопки — доступная ссылка на раздел политики об аналитике. Email в макете взят из текущей конфигурации, но работоспособность ящика ещё не проверена.

### 4.5. Документы

`/privacy/`: обычная читаемая страница с шапкой и подвалом, один H1, дата версии, оглавление с якорями. Разделы: оператор; категории субъектов; цели/данные/основания отдельными строками; способы и сроки; получатели; аналитика и выбор; права/отзыв/обращения; защита без неподтверждённых обещаний; изменения документа.

`/analytics-consent/`: отдельный документ согласия на конкретную аналитику, оператор и получатель, состав и действия, цель, срок и отзыв. Не объединять с рекламными рассылками или договором.

В макете политики приведена структура, а не юридически готовый текст. До подтверждения данных документ не публикуется. Документы оформляются как юридические страницы, не как статьи: без автора, рекламного CTA, related articles или фиктивной FAQ-schema.

Desktop: читаемая колонка примерно 800 px; mobile: 24 px по краям, основной текст от 16 px. При таблице целей на мобильном разрешить управляемую прокрутку таблицы либо использовать последовательные смысловые блоки без потери заголовков.

## 5. Модель состояний и хранения

| Состояние | Баннер | Метрика | Что делает следующий шаг |
| --- | --- | --- | --- |
| Нет валидной записи | Виден | Не загружается | Принятие/отказ сохраняет выбор |
| Разрешено | Скрыт | Разрешён однократный запуск | Настройки позволяют изменить выбор |
| Отказ | Скрыт | Не загружается | Только явное включение меняет состояние |
| Истекла версия/срок или повреждён JSON | Виден | Не загружается | Новый выбор |
| localStorage недоступен | Виден до действия | Только после действия в текущей вкладке | Сообщить, что выбор не сохранится после закрытия/перехода |
| JavaScript выключен | Интерактивного баннера нет | Не загружается, включая noscript | Документы и контакты доступны |

Предложенная запись: ключ `truetell.privacy.v1`, поля `{version: 1, analytics: boolean, savedAt: ISODate, expiresAt: ISODate}`. Срок запоминания — 180 дней как продуктовая настройка, не заявлять его законным обязательным сроком или сроком хранения данных Яндекса. Отдельно определить срок действия самого согласия в документе.

При чтении проверять типы, версию, даты и истечение. Неизвестное значение трактовать как отсутствие решения. Любой сбой загрузки счётчика не должен ломать страницу. До исполнения отложенного callback повторно проверить текущее согласие: отказ между click и idle отменяет запуск. Обработать `storage` event для других вкладок. Не передавать счётчику email, телефон, произвольные идентификаторы или содержимое форм.

Пример обязательных проверок для чистого модуля после выбора совместимого с текущим Node способа импорта TypeScript:

```js
assert.equal(readConsent(null, now), null);
assert.equal(readConsent('{', now), null);
assert.equal(readConsent(JSON.stringify(makeConsent(false, now)), now).analytics, false);
assert.equal(readConsent(JSON.stringify(makeConsent(true, now)), now).analytics, true);
assert.equal(readConsent(JSON.stringify(makeConsent(true, now)), now + 181 * 86400000), null);
```

Результат: повторный визит и отказ работают независимо от видимости баннера.

## 8. Матрица приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Чистый браузер, ждать 10 секунд и прокрутить | 0 запросов tag.js/watch/collect к Метрике; баннер виден |
| Нажать отказ, перейти на другую страницу, перезагрузить | Баннер скрыт, Метрика не запущена |
| Разрешить | Один init, интерфейс не блокируется; Вебвизор выключен |
| Открыть настройки, изменить переключатель, закрыть | Прежний выбор сохранён |
| Сохранить включённый переключатель | Аналитика разрешена, статус объявлен скринридеру |
| Отозвать ранее данное согласие | Отказ сохранён; после перезагрузки новых запросов Метрики нет |
| Отозвать до idle callback | Счётчик не успевает запуститься |
| Две вкладки | Состояние второй вкладки обновляется, отзыв прекращает разрешённый сценарий |
| Повреждённый/просроченный ключ | Счётчик отключён, предлагается новый выбор |
| Storage бросает исключение | Нет падения JS; понятное сообщение; явное решение действует в текущей странице |
| Блокировщик Метрики / offline | Основной сайт и настройки остаются работоспособны |
| JavaScript выключен | Нет noscript-запроса, документы/контакты читаются |
| Keyboard only | Фокус не уходит из dialog, Escape работает, фокус возвращается |
| 320 / 390 / 768 / 1440 px, landscape 844×390 | Нет горизонтального overflow и недоступных кнопок; диалог прокручивается |
| Масштаб 200%, reduced motion | Текст и управление доступны, анимация не обязательна |
| Все страницы с BaseLayout | Нет двойного баннера и повторного счётчика |

Проверять реальное production-условие загрузки: localhost намеренно отключён в текущем коде. Для локальных сетевых тестов использовать контролируемый тестовый hostname или browser routing с production host и перехватом аналитики; никогда не считать «0 запросов на localhost» достаточным доказательством согласия. Не засорять реальный счётчик тестовыми посещениями.

Обязательные команды после реализации:

```sh
node --test scripts/*.test.mjs
npm run lint
npm run build
node scripts/indexnow.mjs --check
```

Дополнительно: браузерная проверка сети и взаимодействий, mobile/desktop screenshots, проверка console errors, ссылок и metadata. Не обещать конкретную метрику производительности без замера; контролировать отсутствие layout shift и лишней гидратации.
