## Проверка

Браузерный сценарий — `scripts/privacy-browser.mjs`. Перед запуском собрать `npm run build`, передать переменные `PUPPETEER_MODULE` (путь к установленному puppeteer-core) и `CHROMIUM_PATH` (локальный Chromium).

Сценарий раздаёт файлы из dist через перехват запросов на тестовом production-подобном origin. Запрос tag.js заменён заглушкой API; реальный счётчик не получает тестовые посещения. Это проверяет нашу загрузку/отзыв и вызовы API, а не внутреннюю реализацию сервиса Яндекса.

Проверены первый визит, отказ, сохранение, отмена черновика, отзыв, перезагрузка, две вкладки, запрет storage, отсутствие JavaScript, размеры 320/390/768/1440. После проверки API-заглушки перед публикацией требуется контролируемая проверка с настоящим счётчиком.

## Перед публикацией

ФИО ИП и адрес получены 26.09.2026 из предоставленного владельцем файла «Реквизиты.PDF.pdf» и внесены в company.ts и обе страницы документов. ИНН и ОГРНИП совпали с существующей конфигурацией. Email в PDF отсутствует; сохранён текущий truetell@bk.ru, его работоспособность отдельно не проверялась. Юридическая часть по фактическим процессам ещё не завершена. Страница `/privacy/` сейчас содержит доступные факты и контакты, она не заменяет полную согласованную политику. Не добавлены выдуманные сроки хранения обращений, расположение баз или гарантии удаления у провайдера. До публикации дополнить документы по реальным процессам и закрыть вопросы уведомления РКН, хостинга/логов, доказательств согласия и обработки обращений из плана.

Итоговые проверки: 16/16 node:test; production build; IndexNow (15 URL); TypeScript; lint — 0 ошибок, 3 прежних предупреждения React hooks. Браузерный сценарий завершён успешно, включая замыкание фокуса при Tab, Escape, возврат фокуса, раскрытые подробности в landscape, отказ при ошибке записи поверх старого согласия. Вызов остановки `destruct` выполняется без перезагрузки страницы.
